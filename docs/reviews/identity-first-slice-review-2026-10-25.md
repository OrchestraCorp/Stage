# P1b 首条身份切片复查

复查范围是已实现的真实认证、主体映射、租户来源准入与自身身份投影，以及开发环境初始化、撤销、幂等恢复和运行装配。沿用[首次实施记录](p1b-first-slice-2026-10-25.md)的阶段边界；未把尚未建设的任职/资源 loader、ServiceGrant、Agent 委托或旧 CommandKernel 全局身份锁列作本轮已完成能力。

## 发现与修复

| 问题 | 可复现行为 | 修复与回归 |
|---|---|---|
| 身份错误响应未完整禁止缓存 | 缺参数的 GET /api/identity/me 返回 422，绕过路由内的 no-store；通用 500 同样遗漏 | 身份 API 专用 ASGI middleware 包住请求错误边界，全部身份响应设置 no-store；覆盖成功、401/403/503、422、404/405、500，并确认不改变其他路由 |
| 开发管理环境仅检查“存在初始化” | 同库先初始化 dev/test，dev 撤销命令可修改 test 专属成员，并在审计中记为 dev | 明确数据库属于单一部署环境；管理锁后、重放前检查环境，不符或混合历史拒绝写入。七项回归涵盖安装、撤销、重放和原环境结果恢复；不清理或改写既有事实 |
| 身份读取可无限等待数据库锁 | 可信认证完成后仍可在 trust/principal/tenant 锁等待中长期占用连接 | 增加默认 10 秒、可配置的整个请求工作预算，覆盖池获取、网络及锁/查询。超时清理后返回 503；真实 PG 持锁场景证明连接和前序 SHARE 锁释放，随后调用可成功 |

另补强真实 IdP 冒烟的正向断言：除 HTTP 200 外，还核验主体类型、目标租户、主体/成员引用、human/service 的 workload 差别和 no-store。协议检查仍按 15 项组合场景记录。

## 复查结论的范围

分别审阅了认证与来源映射、管理事务与迁移、运行资源与 HTTP 合同。当前读取在锁后复核 profile/trust、外部映射、主体、租户来源、成员和 workload，过期以最早截止时间为准；没有发现跨租户或主体类型混用的可复现绕过。已有迁移保留历史 ID/数据，幂等重放及成功提交后丢失响应的恢复路径保持有效。

JWT/JWKS 异常数据独立检查使用临时生成密钥和模拟网络，不涉及真实凭据；检查了无穷/NaN、超大数、错误容器和异常 Unicode，未发现未捕获异常。这些探索结果不加入 pytest 通过数量，也不代替真实 IdP 验收。

身份服务仍通过 Core 服务租约持有存储资源，网络认证不持数据库连接；HTTP client 由组件生命周期关闭。总时间预算限制业务工作，取消后仍需完成连接和事务清理，不能将预算理解为强制丢弃未清理的连接。
