# Stage 架构核对与表达修正记录

本轮把此前讨论收敛到项目文档，并落地了第一批内部执行/幂等/审计/outbox/delivery代码：用户已确认产品愿景、自研方向和“第一期基座优先”；身份、WASM、签名准入与RuntimeHost仍属于待评审设计，不把聊天示意或研究结论写成已完成实现。

## 1. 已确认方向

- OrchestraCorp 是 AI 驱动、安全可靠的分布式工作协作平台，面向跨地点、跨时区、跨组织的人和 Agent。
- Stage 自研组件内核与业务流程运行器，参考 Cordis 的组合思想；Graphon / Dify 只作为研究参考，不作产品依赖。
- 一期先贯通类 Cordis Core、真实身份认证/当前授权、受控 WASM 与签名准入。完整任务业务细节保留到[后续业务切片](business-slice-plan.md)。
- 可验证分布式组织不以区块链或代币为前提；治理分布、人员地理分布与系统多节点部署分别设计。
- 本轮新增内部CommandKernel、执行/审计/outbox/delivery模型与迁移，以及SQLite行为测试；没有新增真实身份adapter、WASM依赖、HTTP接入、生产sink或真实企业配置。

## 3. 必须修正的表达

| 原表达或容易产生的理解 | 修正后的边界 | 依据 |
|---|---|---|
| 初期接入 Graphon，未来再替换 | 用户已决定自研；只保留其设计与场景研究 | 用户方向与现有源码调研 |
| 一期只有 fixture，真实身份等生产前再接 | 一期至少完成一个真实协议 adapter 对隔离测试 IdP 的链路；fixture 是辅具 | 本轮一期要求 |
| WASM 一律推迟到远期 | 受控纯计算 runner、预算和准入提前一期；通用 hostcalls/Component Model/隐私协议后续扩展 | 本轮一期要求 |
| 单进程一期可以直接运行不可信插件 | 修订为单 worker 可信宿主＋受控 runner 进程；Python 组件与 guest 分属不同信任边界 | P1 架构选择、[S1] |
| 拥有服务或已注册能力就有执行权 | 服务解析、业务能力定义、主体权限三者分别验证；所有业务入口统一授权 | Stage AGENT.md / Core 规格 |
| 组件关闭等于撤销任务或业务操作 | disposer 释放运行资源；持久事实只能由新的受权命令改变，外部结果需对账 | Core 与事务边界 |
| WASM 天然对运行方保密 | 宿主可以读写 guest 内存和观察输入输出；隔离执行不等于机密计算 | [S1][S2] |
| WASM 自动给出 ZK、隐私认证或确定性结果 | 这些需要独立协议与验证；可移植执行载体不自动提供这些性质 | [S1] 与待评审设计边界 |
| 签名有效即安全且当前有权执行 | 验签、包内容安全、批准权限、当前业务授权、执行结果分别验证 | 发布/执行分层 |
| Passkey 直接签任意业务文件 | WebAuthn assertion 有规定签名结构；应用将冻结意图摘要绑定 challenge，并核验上下文和一次性使用 | [S3] |
| 普通 MFA 登录即批准这次发布 | 登录认证需要与不可变发布意图严格关联；普通认证结果不能充当文件签名证明 | [S3] 与应用协议设计 |
| K-of-N 多人批准就是阈值签名 | 独立批准证据是治理策略；密码学阈值签名涉及共同私钥份额及协作协议 | [S6] |
| VC 签名有效意味着声明真实、匿名或唯一人 | 需要另定发行方信任、主体绑定、状态/撤销与所需披露机制；数据模型不自动提供这些保证 | [S4] |
| DID 自动证明自然人、员工身份或岗位 | 密钥控制与验证关系不等于真实主体或组织任职；method、注册/解析与绑定单独定义 | [S5] |
| 一个 nullifier 哈希公式就构成可用隐私防重协议 | 聊天公式仅示意，不作为实现依据；未选经审查的协议前不宣称匿名、防多身份或去关联 | 本轮纠正，尚无采用方案 |
| 把 JSON 排序就可签任何数据 | 确切字节、数据域、重复键、数值与字符规则必须冻结；若采用 JCS 必须遵守其完整约束 | [S7] |
| WASM 返回 allow=true 就能授予岗位或命令权限 | 资格输出是候选结果，宿主当前授权与领域不变量仍是最终强制入口 | P1 最小切片 |
| WASM trap/超时证明所有外部效果没发生 | 仅能解释相应计算尝试；副作用调用须有独立结果与对账，P1 guest 不开放此能力 | [WASM 设计](wasm-host-design.md) |
| Dify 的所有功能都是 Graphon 自带 | Graphon 提供图执行与快照；Dify 另有画布、发布、身份与持久化集成；参考结论限定固定源码范围 | [Dify 对照](dify-workflow-study.md) |
| Core 34 场景代表全部基座已实现 | 34 个已定义，执行/通过为 0；新增身份/WASM/对象/联调分别统计 | 当前文档与源码状态 |

关于自研隐私协议，不能从公开身份字段的简单哈希推导匿名性；也不能从一把密钥推导唯一自然人。具体防重复、范围伪名、撤销和证明绑定必须依据选定协议评审，不在 P1 自行拼接密码方案。

## 4. 共同设计约束

1. **身份和事实由可信端提供。**执行上下文只保存经过验证的引用，提交前重验当前状态；未来隐私凭证场景仅取得足够判断的最小可信输入。
2. **运行版本与当前安全状态分开。**实例保留旧定义，撤销和禁止执行仍使用当前状态；缺少旧实现时阻断，不回退 latest。
3. **WASM 计算不持业务事务。**计算前取受限事实快照，计算后核对行与集合 revision、授权和发布状态，再提交结果。
4. **幂等身份跨重试稳定。**attempt 可以变化；同一业务命令不能因超时或流程恢复换 key 重放副作用。
5. **状态机不混用。**组件生命周期、身份/凭据、发布激活、runner attempt、命令结果、流程实例各有状态及恢复路径。
6. **可信平台规则独立。**业务蓝图不能修改信任根、验签开关或自身批准规则。签名后内容若变化，重新批准。
7. **执行证据有限。**普通运行回执和审计用于可追溯，不自动构成密码学可验证计算或绝对防篡改；需要更强证明时另定威胁模型。

## 5. 本轮核对的一手来源

访问核对日期均为 2026-10-24。链接用于说明已核对的技术边界，不代表 Stage 已实现对应标准或认证。文档发布版本与产品依赖版本分别固定，不能把网页是“latest”当成构建锁。

- **[S1]** [Wasmtime Security](https://docs.wasmtime.dev/security.html)：WASM/宿主接口与隔离边界。具体执行预算、预编译产物和 Python API 依据另列在 WASM 文档。
- **[S2]** [Wasmtime Memory 示例](https://docs.wasmtime.dev/examples-memory.html)：宿主通过 API 访问 guest 线性内存；支持“WASM 不对宿主保密”的边界。
- **[S3]** [WebAuthn Level 2](https://www.w3.org/TR/webauthn-2/) §6.3.3、§7.2：认证断言签名与验证。采用稳定基础断言语义，不依赖尚未选型的通用数据签名扩展。
- **[S4]** [Verifiable Credentials Data Model 2.0](https://www.w3.org/TR/vc-data-model-2.0/) 信任模型、验证与隐私说明：凭证模型与验证者信任政策分开，所选安全机制决定实际披露能力。
- **[S5]** [DID Core 1.0](https://www.w3.org/TR/2022/REC-did-core-20220719/) §5.2、§5.3、§9.2：验证方法、用途关系与控制/主体绑定；不把 DID 当岗位或唯一自然人证明。
- **[S6]** [RFC 9591 FROST](https://www.rfc-editor.org/rfc/rfc9591.html) §1：共同私钥份额的协同阈值签名；该 RFC 标记为 Informational，引用只为概念区分，不作采用承诺或行业认证。
- **[S7]** [RFC 8785 JCS](https://www.rfc-editor.org/rfc/rfc8785.html) §3：规范化 JSON 的数据限制与序列化规则；本轮 manifest 编码仍需按选定 profile 冻结。

身份的 OIDC/OAuth、token 与撤销来源见[身份专项来源](identity-and-authorization.md)。Cordis 论文/DSH 固定源码和 Graphon 固定来源沿用既有研究记录，没有把本轮文档校验冒充重新执行它们的测试。
