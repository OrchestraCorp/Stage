# 人员管理员首个切片

本轮落实已批准的[管理中心边界](maestro-stage-administration.md)：真实首管接受提名、已有人员目录、有限普通任职授予／撤销、结果恢复和本管理域审计。Maestro 实现管理体验，Stage 强制执行；本文件不是完整 IAM 或生产安装验收。

具体初始化、API 调用顺序与错误恢复见[运行及联调手册](../deployment/identity/human-administration.md)。

## 1. 固定范围与责任

- 复用现有 Principal、成员经历、角色版本、任职、OAuth/MFA 与 PostgreSQL；不新增认证栈、运行时层级或常驻服务。
- 首切片是组织级人员管理，能读取本组织当前人员的最小标识和状态。现有表没有人事姓名／部门归属，不从登录名或授权 scope 推断部门。完整组织岗位仍按 P3 推进。
- 首版只启用一名首管。其管理任职使用独立管理动作和固定角色版本；普通业务 loader 不将管理角色转换成业务读取权。后续多人管理、管理权转交和紧急恢复须补专门协议，不能复用普通角色授予接口。
- 初始可授清单按精确角色 revision＋内容摘要＋scope＋最长有效期登记；使用权与授予权分开。不得授予自己、管理角色或未登记角色版本；不隐含包含子 scope。
- 每次授予必须有明确到期时间，最长一年且不能超过目标成员有效期。旧成员经历、停用主体和失效 scope 不可获得新任职；已有任职不自动迁移到新角色版本。

普通任职自然到期不会自动改写持久状态；同一角色版本和 scope 再次授予前，须显式撤销旧 active／suspended 任职。撤回允许目标成员已经结束或停用，因为它只减少旧权限。当前撤回仍要求登记清单中的角色内容和 scope 有效；停用或损坏这些依赖后的清理按受控修复处理，不以扩大清单绕过。

管理任职列表保留角色已停用后的既有任职事实。返回的 status 是任职行状态，与其有效期、角色或成员可用性共同决定实际权限；列表和历史回执均不能用作授权判断。

## 2. 首管提名与接受

部署操作者通过本机受控命令明确指定已有 human、当前成员经历、精确认证映射和 profile，以及可授清单。提名有效期最多一小时；创建 pending 管理权限记录和 suspended 管理任职。尚未接受的提名可凭预期版本重提名，旧提名任职失效并保留审计。`accepted_at` 一旦存在，初始化入口永久关闭，不能靠角色撤销或账号停用重新打开。

被提名人员从 `/administration/me` 发现自己的提名，用当前登录凭据及预期版本接受；服务器原子激活管理任职、记录接受和审计。首次登录不自动成为管理员。本机提名并不代替人员本人接受，也不允许管理员知道员工密码。

前提是部署已经存在经明确登记的人员、认证来源和 MFA。现有 dev/test 身份安装工具仍不等于完整生产安装器；新提名命令也不创建人员、密码或认证来源。初始化未知结果按原键恢复；不能将本机权限带入 HTTP 信任模型。

首管管理资格不设自动到期，候选成员不能有自动结束时间。首切片 HTTP 不提供管理角色撤销、自我授予或管理授权修改；这些路径无法删掉最后管理入口。此保护不覆盖 OS 紧急操作、账号丢失或未来离职／停用入口，不能宣称全系统末位管理员保护已经完成。

## 3. 管理操作矩阵

| 操作 | 当前身份与范围 | 版本／持久结果 |
|---|---|---|
| 本人管理提名／任职发现 | 当前人员及固定成员经历；只返回本人的记录 | 返回管理任职和权限版本，不是权限票据 |
| 接受首管提名 | 精确被提名人员／映射／profile，提名未到期 | 预期权限版本、幂等键、原子激活及审计 |
| 人员目录／详情 | 当前管理任职，组织级人员最小投影 | 分页，无跨页快照承诺 |
| 查看人员任职 | 当前管理任职；只投影本组织该人员的普通角色任职 | 分页，标明当前状态与版本 |
| 授予普通任职 | 登记清单内精确角色版本、scope、期限；禁止自己 | 预期成员版本／管理权限版本，原键恢复 |
| 撤销普通任职 | 同一清单范围，禁止自己和管理角色 | 预期任职版本／管理权限版本，原键恢复 |
| 查询操作结果 | 当前管理权限下，原人员自己的原幂等键 | 返回原结果，不重新执行 |
| 管理审计 | 当前管理任职，只限本管理切片 | 有界分页，不开放任意认证事件／业务审计库 |

所有管理入口含读取都要求组织 MFA 策略 required，并在现有精确 profile/ACR/AMR 校验之外要求密码＋TOTP、最近 300 秒认证；刷新 token 不延长认证时间。当前身份、来源、管理任职、角色内容及 scope 在读取后／提交前重新检查，等待锁不能延长有效期。

## 4. API 与事务合同

公开入口使用 `/api/v1/administration`，具体 DTO 以同步 OpenAPI 为准。`/me`、`/activation` 使用本人认证；其他操作显式选择管理任职。客户端不可选组织、提交可信 actor 或通过更换任职绕过拒绝。全部响应含错误使用 no-store。

命令键按组织、真实人员、管理命令版本与原键唯一；动作、目标、输入、选定管理任职进入摘要。同键不同意图冲突，重放仍验证当前管理权限。审计使用 human actor、认证证据白名单、request_id、前后状态及必要原因，不记录 token、密码或因素秘密。

写者按命令键 → Trust S → 人员 Principal S → 组织 X → 目标状态的顺序持锁；目标人员锁必须在组织锁前取得。只读使用组织 S。复用现有协调和事务所有权协议，安全事实变更使用专门管理服务，不嵌入禁止修改安全事实的普通工作项 handler。外部验证／浏览器交互不持数据库锁。

SQL／网络异常不一概等同回滚。提交开始后无法确认结果时返回 COMMIT_OUTCOME_UNKNOWN 和原键恢复地址；客户端保留原意图。所有读取、重放、结果和审计分别重新授权，已提交审计不因角色撤销删除。

## 5. 本轮验证与后续接缝

验收覆盖真实签名身份、近期 MFA、初始提名／重复接受、越权与自提权、精确角色内容、scope／期限、旧成员经历、版本冲突、同键竞争、授权撤销竞争、未知提交恢复、HTTP 边界与迁移。PostgreSQL 是锁与事务权威验收；SQLite 只是快测。

本切片后继续员工激活、本人设密／TOTP、安全恢复与组合离职；再逐步完成应用／策略管理与更完整审计体验。Maestro 页面和真实客户端联调单独记录，服务端通过不等于完整管理中心完成。

本轮完整验证和架构复查见[实施记录](reviews/human-administration-first-slice-2026-10-26.md)：PostgreSQL1701通过／10跳过，SQLite快测1600通过／103跳过，Chromium两场景通过；开发服务已备份、迁移并重启验证。迁移不会自动建立管理员。
