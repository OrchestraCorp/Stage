# Maestro 管理中心与 Stage 管理接口边界

2026-10-26 用户确认：**身份、人员、组织与权限的完整管理体验融入 Maestro；Stage 负责正式管理后端和安全事实。** 云开发设备继续承担 Stage，本地承担 Maestro。此决定明确产品归属与共同验收要求，不表示管理 API、页面和具体规则已经实现，也不自动扩大为全功能 IAM／PAM 或完整 OA 工作流。

本轮在 Stage 仓库记录并实施接口与产品边界，没有修改本地研发的 Maestro 代码。现有认证／本人账户安全和人员业务接口见[联调合同](maestro-stage-p1b-handoff.md)；此前管理缺口见[完备性评估](reviews/enterprise-identity-completeness-2026-10-26.md)。

随后已获批准实施[首个管理切片](human-administration-first-slice.md)：Stage 提供首管提名／本人接受、现有人员目录、有限普通任职授撤、原键恢复及本切片审计。具体请求见[OpenAPI](../contracts/openapi.yaml)，本地 Maestro 页面与实际联调仍单独验收。

员工开户后续切片见[员工开户与一次性激活](employee-onboarding.md)，包括新增 HTTP 合同与秘密交付规则。`/administration/me` 现在返回明确的管理角色 revision、任职行版本和 action 集合；显示按钮可据此提示，服务端仍逐次授权。

## 1. 产品责任

| 责任 | Maestro | Stage |
|---|---|---|
| 管理员登录与工作身份 | 发起系统浏览器登录、选择明确任职、展示当前管理范围及认证状态 | 原生 OAuth/OIDC/MFA、当前主体／成员／任职核验、管理操作的强度与新鲜度要求 |
| 人员及组织管理 | 列表、筛选、详情、创建／激活、入离职与调岗操作体验 | 数据模型、状态机、目标范围、版本与原子变更；组织scope不冒充完整部门树 |
| 角色与任职 | 角色能力说明、版本差异、授予范围／期限、影响预览与确认 | 稳定action、可授角色与范围上限、当前操作者权限、禁止越权／自提权规则 |
| 账户与会话安全 | 本人安全中心、获权管理员的停用／恢复／会话处理页面 | 单次证明、凭据与会话失效、因素恢复、敏感操作核验 |
| 应用与登录策略 | 客户端登记／停用、回调与准入状态、MFA配置及风险提示 | client/profile/binding及组织策略、秘密生命周期、来源准入与撤销 |
| 审计与结果恢复 | 有权范围内查询、状态说明、操作详情及未知结果恢复 | 审计可见性、分页／导出合同、原键恢复、脱敏、保留与清理 |

管理身份仍使用已有 Principal 与认证系统；管理能力由角色／任职和目标范围决定。页面或菜单可见不产生权限，Maestro 的客户端标识也不是管理员身份。Stage 每次管理请求以及提交前都独立验证。

本人账户安全沿用当前账户所有者的认证合同，不要求拥有管理任职。操作他人的账户必须使用正式管理授权和对应接口，不能给本人接口增加任意人员参数来代行管理。

Stage 现有 issuer 托管的登录、TOTP绑定／恢复、同意和退出确认页继续属于认证流程。Maestro 从系统浏览器进入这些页面，保持 issuer 主机和 Cookie 安全边界；它们不演变成另一套独立人员管理后台。个人密码、TOTP种子、恢复码不进入模型会话或通用工具上下文。

## 2. 完整管理体验的范围

以下是管理中心的目标模块，可分批交付；每批必须形成实际可操作闭环，不能只有页面或开发脚本。

管理中心是产品入口，不是把所有模块提前实施的阶段。P1b 补齐人员／账户、有限角色任职和必要审计的最小管理闭环；组织／岗位模块的完整目录、多岗位责任、替补、资格和工作窗口仍按 P3 推进。P1b 使用已有组织授权根与明确 scope，不把 scope 临时冒充部门树。应用和安全管理按各自合同交付；本表不是全部追加到 P1b 的退出清单。

| 模块 | 完整体验至少包含 | 当前后端状态 |
|---|---|---|
| 人员与成员 | 目录／详情、开户激活、成员状态、离职冻结、复职边界及操作结果 | 目录／详情、员工开户、独立 issuer 密码＋TOTP 激活及重发撤销已实现；组合离职与客户端页面另验 |
| 组织、岗位与范围 | 组织关系／职务及其与授权scope的映射、岗位责任说明 | 已有授权scope与assignment，完整组织／岗位目录未实现 |
| 角色、任职与权限 | 版本化角色、授予／撤销／期限、管理范围、权限解释和变更影响 | 首管与精确清单内普通任职授撤已实现；多管理员、管理权转交、角色发布和影响预览待后续 |
| 本人账户安全 | 改密、因素恢复／重绑、会话和应用同意管理、重新登录与错误恢复 | 相关Stage本人API已实现，Maestro实际体验另验 |
| 管理员账户安全 | 他人账号停用／恢复、因素恢复、会话撤销、原因与通知交付 | dev/test本机操作存在；正式管理者授权与产品流程未实现 |
| 应用与认证策略 | 企业受控应用、redirect配置、来源准入、MFA策略、版本冲突及秘密安全交付 | 内部协议与dev/test管理工具存在；正式管理界面/API未实现 |
| 审计与操作记录 | 受权分页检索、操作责任与结果、恢复查询、适用的导出和保留说明 | 本管理切片分页审计／原人原键恢复已实现；全域审计、导出与保留运营待后续 |

“完整”是指上述身份管理范围中，用户能够理解状态、完成动作、处理失败和恢复结果。任务流程画布、通用报表、Passkey、目录联邦和多租户并不因管理中心要求而自动进入本轮。

## 3. Stage 在前端实施前应提供的合同

1. **管理操作矩阵。** 每个动作固定操作者所选任职、目标类型／范围、可授角色和期限上限、近期MFA要求、预期版本、确认意图和审计字段。角色使用权与授予权分开，首管交接、最后管理员保护和应急恢复另有明确协议。
2. **查询与可操作性投影。** 提供受权人员／角色／scope等列表与详情、分页和必要筛选；可返回当前可操作项、原因码、版本及影响预览供UI使用。投影只是当时的展示依据，提交仍需重新判断，不能发一份长期可复用的allow票据。
3. **版本化API。** 公开管理接口遵循 `/api/v1` 与OpenAPI；具体路径、DTO和action名在实现前评审冻结，本文件不虚构已存在端点。认证协议、资料接口、本人账户安全与操作他人的管理接口职责分开。
4. **结果和恢复。** 普通管理状态变更使用稳定幂等身份、expected_version、原子审计与可恢复结果。并发修改、权限撤销、认证过期、网络超时和commit unknown需提供机器可读语义；Maestro保留原键／原意图，不自动换键重做或静默换任职。
5. **一次性秘密例外。** 激活、重绑码、客户端秘密按单次交付合同处理，不能为“幂等”反复返回旧明文。UI在安全边界内完成仅一次的展示／交付，丢失或未知时走明确恢复；不在列表、日志、审计或AI上下文中展示秘密。
6. **部署拓扑。** 本地桌面沿用系统浏览器＋PKCE及OS安全凭据存储。若Maestro Web/PWA也接入，应单独冻结其client类型、origin、BFF／Cookie／CORS／CSRF合同，不能直接套用桌面或默认开放跨域。

现有dev/test本机CLI的 `bootstrap_operator` 信任依据不能直接用于上述HTTP接口。正式管理请求必须识别真实人员、当前管理权限与目标；使用专门受控写者事务，而不是把授权变更塞入禁止修改安全事实的普通work handler。

## 4. 前后端共同验收

建议首个闭环为：首管完成交接 → 管理员登录Maestro → 创建／激活员工 → 授予有限任职 → 员工完成登录并选择该任职 → 安全重置或离职冻结 → 管理员查看审计与操作结果。

至少验证：

- 普通人员不能调用管理操作；隐藏按钮和直接调用API得到一致边界，Stage始终是强制执行点。
- 管理员不能越范围授予、借别人的任职操作或按未授权规则自提权；当前任职和目标在UI中明确可见。
- 认证过期时重新认证，权限撤销时停止操作；预览后状态变化不允许靠旧页面继续提交。
- 版本冲突需要重新读取并由用户确认新意图；未知结果按原键恢复，不能把“点击失败”当成已回滚。
- 激活／重绑／客户端秘密只在规定步骤交付；取消、丢失响应和重入都有明确处理，不泄露给模型或日志。
- 离职分别验证Stage业务资格、原生登录／SSO和第三方RP本地会话的约定边界，不使用模糊的“全部已退出”提示。
- 适用的加载、空列表、无权限、错误、长操作、键盘操作与可访问性状态可用；本地缓存按人员／部署隔离，并在退出／身份切换时清理敏感投影。
- 同一操作能从Maestro请求关联到Stage结果及受权审计；实际桌面／Web入口分别记录证据。

Stage API通过、客户端页面完成和真实产品联调通过是三个里程碑。尚未由两端验证的模块标为部分完成；开发CLI和合成浏览器脚本不替代Maestro实用性验收。

## 5. 分工与推进

云端Stage先冻结管理规则、API／状态与错误合同，并提供不含真实秘密的fixture与契约测试；本地Maestro按相同合同实现管理模块和安全交互。可以用约定fixture并行开发页面，正式验收仍必须连接真实Stage。

每个垂直切片同步OpenAPI、管理action、数据库迁移（确有需要时）、测试、联调说明与产品完成状态。首个人员／账户／有限任职管理闭环补足P1b身份产品；完整管理中心按模块逐步交付，不作为P1b新增的整个平台前置条件。WASM接口设计可并行，P1c/P1d、后续任务与P3组织岗位／持久流程仍按既定路线推进。
